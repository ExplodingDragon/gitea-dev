# Gitea 服务端

Gitea 是 Codespace 的业务控制面：它判断谁可以创建和访问环境，保存用户可见状态，签发短期凭据，并把生命周期操作交给 Manager。运行平台的实现见[运行平台](runtime-platform.md)。

## 用户体验

Codespace 使用 Gitea 现有的信息结构：仓库、提交和合并请求页面提供当前上下文的创建入口；`/-/codespaces` 提供跨仓库列表；详情页展示状态、访问入口、资源使用、设置和操作日志；用户设置与站点管理分别维护个人和全局对象。

创建使用“解析后确认”流程。Gitea 锁定提交并解析 Dev Container 配置，然后让用户确认运行环境、配置来源、附加仓库权限、会注入的 Secret 名称和自动停止设置。运行环境必须明确选择；短暂离线的 Manager 不会让环境选项消失，因为操作可以排队等待恢复。

列表与详情只展示用户作出决定所需的信息。Runtime UUID、Pod、路由目标等平台诊断数据留在 Manager 管理面和服务日志。

**设计如此：**创建入口依附仓库上下文，集中列表负责管理已有环境。这样创建时无需重复选择仓库，跨仓库管理也有稳定入口。

### 实现验收点

- 用户可以从分支、标签、提交和合并请求进入同一创建确认流程。
- 没有可用环境时页面给出基础设施状态，并且不创建业务记录。
- 配置、权限或 Secret 范围变化时，提交要求重新确认。
- 集中列表只返回当前用户的数据，并支持分页和状态筛选。

## 权限与身份

Codespace 归创建用户所有。页面、表单和令牌接口都从当前登录用户重新查找对象，URL 中的 ID 或 UUID 只用于定位，不能代替权限检查。

创建至少要求主仓库代码读取权限。Dev Container 需要的附加仓库由用户逐项授权；运行时权限是用户当前权限与已确认范围的交集。个人 Manager 只服务其所有者，站点全局 Manager 可以服务任意用户。

### 实现验收点

- 修改请求中的对象、仓库、用户或 Runtime 标识不能访问他人数据。
- 用户失去仓库权限后，后续签发的运行凭据同步收窄或停止。
- 附加仓库授权不会扩大用户原有权限。
- 普通用户无法管理全局 Manager、模板或他人的个人对象。

## Manager 与调度

用户或站点管理员在 Gitea 创建并命名 Manager 记录，再生成一次性注册 Secret。Gitea 只保存 Secret 摘要；Manager 注册后声明访问地址、主机指纹和环境标签。

创建操作先以未绑定状态入队。Manager 拉取任务时提交当前可接受的标签和容量，Gitea 按所有权、标签和排队顺序选择候选，并用条件更新保证唯一领取。Manager 分配 Runtime UUID 并完成绑定，后续 resume、stop 和 delete 都回到同一 Manager。

环境标签只参与首次创建和调度。已有环境使用创建时确定的运行配置，标签变化不会迁移环境。

### 实现验收点

- 注册 Secret 只在生成时显示，刷新页面无法再次取得明文。
- 并发领取同一操作时只有一个 Manager 成功。
- 个人 Manager 无法领取其他用户的操作。
- Runtime UUID 绑定后保持稳定，后续操作不重新调度。

## 生命周期与展示

Gitea 为 create、resume、stop 和 delete 建立带版本的操作。Manager 的领取、续期、日志、Runtime 信息和结果必须匹配当前身份、绑定和操作版本。完整转换规则见[生命周期](lifecycle.md)。

操作日志是带单调字节偏移的追加流。页面按偏移增量加载，并在用户查看历史时保持滚动位置。CPU、内存、磁盘和 Endpoint 属于带代数的展示数据；过期时显示暂不可用，不改变业务状态。

### 实现验收点

- 非法状态转换在创建操作前返回明确错误。
- 旧操作版本的续期、日志、Runtime 信息和结果不会覆盖当前状态。
- 长日志按上限分页获取，不阻塞页面交互。
- 展示数据过期不把 running 推测为 stopped 或 failed。

## 凭据与访问

Gitea 按用途签发运行期 Git/API Token、一次性浏览器 Open Code 和 Gateway 会话授权。Git SSH 私钥由 Runtime 生成并保存在 PVC，Gitea 只接收公钥；用户 Secret 加密保存，运行时只按名称与当前仓库范围请求。

Manager 在 create、resume 或恢复运行材料时向 Gitea 请求当前有效内容，并将明文写入 Runtime 易失目录。stop 和 delete 撤销运行期 Token；resume 重新签发。HTTP Git 与 SSH Git 各自使用对应信任配置，SSH 主机信任只在选择 SSH 传输时参与校验。

### 实现验收点

- Token 权限不超过已确认范围与用户当前权限的交集。
- Open Code 只能使用一次，并且只打开指定 Codespace 与 Endpoint。
- 私钥和 Secret 明文不进入 Gitea 日志、操作日志或读取响应。
- Secret 撤权后，后续运行材料不再包含该值。

## 配置与后台任务

Gitea 配置只表达业务入口和策略，例如启用状态、操作超时、日志限制、Git 传输和 Gateway 对外地址。Kubernetes、镜像、RuntimeClass 和缓存配置由 Manager 管理。

后台任务处理排队超时、操作租约、自动停止、失效凭据和 Manager 状态核对。任务使用数据库条件更新保持幂等，允许多个 Gitea 实例重复扫描。配置示例列出代码支持的全部项目、默认值和使用原因。

### 实现验收点

- `app.example.ini` 与代码中的配置、默认值和语义一致。
- Gitea 启动不依赖 Manager 在线。
- 多实例后台任务不会创建重复操作或重复撤销凭据。
- Gitea 页面和配置中不出现 Kubernetes 实现选项。
