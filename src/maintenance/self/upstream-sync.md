# 上游同步流程

## 固定来源和本轮范围

获取并记录官方主线、Codespace PR #38337、Pages PR #40071 的远端头，以及更新前 self 提交和数据库版本。明确本轮是指定 PR 更新还是同时更新官方主线；分别记录“远端最新主线”和“本轮实际包含主线”，使范围可核验。

确认内层 self、外层 main，记录已有用户改动。只有来源发生变化的 PR 需要新增合并；已合入且没有变化的 PR 保留原历史。本轮为 Codespace `09670abbde`，Pages `5000d55fb2` 沿用，实际包含主线仍为 `23836eb610`。

**实现验收点**

- 记录每个输入的完整哈希、日期及更新前数据库版本。
- PR 远端头与实际合并第二父相同。
- 用户现有修改和任务范围明确区分。

## 正常业务合并与独立数据库安排

先生成正常合并树并保存哈希，再以双父合并接入发生变化的 PR。业务代码按双方当前实现正常组合；如有业务文本冲突，逐项记录组合依据。合并第二父保留 PR 原始提交，使下一轮增量可从该头继续。

审核自动合并的数据库结果，特别检查 Git 重命名追踪是否把新 PR 结构写入已发布 self 补丁。合并时保留历史迁移的含义，再以独立普通提交增加本轮实际需要的变化。本轮采用无业务文本冲突的正常树，因此可直接逐文件证明所有非数据库代码相同。

**实现验收点**

- 每个更新的 PR 有独立双父合并。
- 已发布迁移和官方文件保持来源内容。
- 最终 `modelmigration/` 以外与确认的正常合并结果一致。

## 迁移增量与兼容范围

官方新增迁移保持原 `vXXX.go` 和测试，self 只在末尾注册执行位置。两个自维护 PR 的增量沿原来源身份递增 patchN。新迁移测试使用上一版 self 的版本表与旧结构调用完整迁移器，同时覆盖迁移后的再次启动。

兼容范围为 self 连续历史。数据处理按真实结构差异设计：可保持原值的配置直接保留，需要明确丢弃的运行数据先写清对象和理由。本轮迁移 374 的旧 Codespace 清理已单独审阅；以后仍逐项判断变化，375 之后的实例不会再次执行这项清理。

**实现验收点**

- self 编号连续追加，文件身份与执行编号在映射表对应。
- 新版本存在完整升级、保留范围及重复启动测试。
- 有一次性删除时，说明删除项、保留项、错误处理和部署收尾步骤。

## 验证与交付

通过仓库 Make 目标运行格式化、依赖与生成检查、lint、构建、后端、前端、迁移、集成和端到端测试。多数据库迁移验证使用隔离测试库和 `GOTEST_FLAGS='-timeout 40m -count=1'`，避免测试缓存掩盖数据库切换。格式检查通过工作树与暂存区比较，先暂存已审核修改，再运行检查并复核生成物。

环境差异如实记录测试名、工具版本和实际值；新增问题在任务范围内修复。验证后清理本轮测试产物和临时数据库容器，更新维护说明、目录与 AGENTS。重读 `/tmp/todo-mi.md` 时按其实际内容核对，不把旧任务说明误认为本轮迁移计划。

先推送内层 self，再提交推送外层指针和维护记录。部署到真实实例另按 patch4 发布说明执行，代码验证不代表已操作线上数据库或集群。

**实现验收点**

- 验证记录区分通过、已知环境问题和未执行项目。
- 正常合并树差异、官方文件、历史补丁和版本列表均完成审计。
- mdBook 构建通过，外层只暂存本轮维护范围。
- 内外远端提交与本地结果一致；实际部署状态单独说明。
