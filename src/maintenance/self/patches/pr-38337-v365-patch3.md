# Codespace PR #38337：来源迁移 365 patch3

## 来源与执行位置

Codespace 提交 `79e802a5fa34dcfba4730d800b1b105184960877` 改进调度流程，并从来源迁移 365 的 `codespace` 表定义中删除 `queued_timeout` 索引。旧 `self` 已经通过迁移 365 创建过该索引，因此当前分支把删除动作安排为实际迁移 371，完成后数据库版本为 372。

**实现验收点**

- 文件名为 `pr-38337-v365-patch3.go`。
- `DropCodespaceQueuedTimeoutIndex` 注册为 `self` 迁移 371。
- 来源提交 `79e802a5fa` 和移植提交 `dc1a1f5b68` 都可从当前历史解析。

## 实现理由

迁移通过当前数据库方言读取 `codespace` 表索引，匹配 `queued_timeout` 后使用方言生成的删除语句。找不到该索引时直接成功，因此全新数据库、已清理数据库和重复执行都得到同一结果。代码只删除明确目标，不改变 `running_timeout` 或其他调度索引。

**实现验收点**

- 索引存在时被删除，不存在时迁移仍成功。
- `running_timeout` 在迁移后继续存在。
- 实现使用数据库方言提供的索引读取和删除能力。

## 直接测试

直接测试建立旧结构，创建 `queued_timeout` 与 `running_timeout`，写入一条 Codespace 数据，然后连续执行两次迁移。测试再次读取索引与数据，证明迁移是幂等的，且不会因删除索引丢失行。

**实现验收点**

- `TestDropCodespaceQueuedTimeoutIndex` 在 `make test-migration` 中通过。
- 测试验证目标索引消失、保留索引存在、原数据仍可读取。
- 昨天版本 368 的 `self` 最终会执行本项并到达版本 372。
