# Codespace PR #38337：来源迁移 365 patch1

## 来源与执行位置

本项来自 Codespace PR #38337 的基础迁移，首次来源提交为 `1c0f24e4fd7755b47a22e3cb89c3fc366b5901ab`。文件名中的 `v365` 表示来源迁移身份；它在 `self` 中也实际注册为迁移 365，完成后数据库版本为 366。

该迁移建立 Codespace、Manager、Gitea 令牌、SSH 密钥、打开令牌、权限授权、用户密钥和 Dev Container 模板等基础结构，并写入默认模板。它是 `self` 在上游迁移 364 之后的第一项自维护功能迁移。

**实现验收点**

- 文件为 `modelmigration/v29/pr-38337-v365-patch1.go`。
- `migrations.go` 将 `AddCodespaceTables` 注册为迁移 365。
- 迁移完成后的数据库版本为 366，默认 Dev Container 模板存在。

## 与当前 PR 头的关系

当前 Codespace 头 `68bcefaa69` 因上游新增迁移而把完整建表操作顺延到来源迁移 368。`self` 保持已经发布的实际迁移 365，不重复执行来源 368 的完整建表。来源后来加入的 Manager 注册令牌和索引删除分别由同一来源迁移身份下的 `patch2`、`patch3` 表达。

这种拆分使老 `self` 数据库只执行新增部分，同时让全新数据库最终得到当前 PR 头要求的结构。

**实现验收点**

- 当前迁移列表只注册一次 `AddCodespaceTables`。
- Manager 注册令牌由 `patch2` 建立，排队超时索引由 `patch3` 删除。
- 当前 PR 头 `68bcefaa69` 是最终 `self` 的祖先。

## 关键数据库行为

Codespace 在 Manager 开始创建操作前可以没有运行时 UUID，获得 UUID 后要求唯一。迁移使用来源实现的唯一索引和 SQL Server 条件处理。基础迁移还创建排队超时索引；该索引在当前来源代码中已停用，并由实际迁移 371 清理。

**实现验收点**

- Codespace UUID 唯一约束测试通过。
- SQL Server 条件允许多个尚无 UUID 的排队记录。
- 从旧 `self` 升级后，基础数据保留且废弃索引由迁移 371 删除。
