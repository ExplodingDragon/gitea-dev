当前 Codespace 头 `0f1c19ba10e2d6e026efd0f63e435e545fc3d230` 已包含上游数据库版本 370，因此把完整 Codespace 迁移放在来源 `v370.go`。self 已经发布基础结构、Manager 注册令牌和后续索引清理，最终结构由 patch1、patch2、patch3 共同提供，不重复注册当前 PR 的完整 `v370.go`。

保持最初 `v365` 身份，可以在 PR 再次变基时继续把后续变化归到同一来源系列；当前 PR 所在槽位变化不会改写已发布 self 历史。

## 关键数据库行为

Codespace 在 Manager 开始创建操作前可以没有运行时 UUID，获得 UUID 后要求唯一。基础迁移使用来源实现的唯一索引，并为 SQL Server 使用只约束非空 UUID 的条件索引。迁移最初创建的 `queued_timeout` 索引在 patch3 中清理。

**实现验收点**

- Codespace UUID 唯一约束测试通过。
- SQL Server 条件允许多条尚无运行时 UUID 的记录。
- 旧 self 数据在 patch3 清理索引时保持不变。
