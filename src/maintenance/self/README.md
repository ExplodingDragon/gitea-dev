# Gitea self 分支维护总览

## 维护目标

`gitea/self` 是本项目实际部署并持续升级的 Gitea 分支，`gitea-dev/main` 负责固定已经验证的内层提交并保存维护记录。业务代码采用 [Codespace PR #38337](https://github.com/go-gitea/gitea/pull/38337)、[Pages PR #40071](https://github.com/go-gitea/gitea/pull/40071) 与它们包含的上游代码的正常合并结果；self 只为自己的已发布数据库序列安排不同的迁移执行编号。

当前内层提交为 `8d65b612a28b71a2fef99c5534a19ec2344bd783`，上游固定在 `23836eb610b6673dc4ef7001d432e48dd3af1537`，Codespace PR 固定在 `0f1c19ba10e2d6e026efd0f63e435e545fc3d230`，Pages PR 固定在 `5000d55fb2b0c3312fe4a49e3716bd871efc1ce7`。当前期望数据库版本为 374。

**实现验收点**

- 内层当前分支为 `self`，远端 `origin/self` 指向 `8d65b612a28b71a2fef99c5534a19ec2344bd783`。
- 三个固定来源都是当前 self 的祖先。
- `modelmigration.ExpectedDBVersion()` 返回 374。

## 兼容范围

self 保证已经沿 self 分支运行的实例继续升级。本轮最重要的升级锚点是上一版 `self@53d76a7ab066085c21af9098862392ba1d2fc420`：该版本数据库为 372，升级后依次执行迁移 372 和 373，到达版本 374。更早的 self 数据库继续沿同一条连续序列补齐迁移；全新安装由当前代码创建最终结构。

上游和两个单独 PR 在迁移 365 之后使用了与 self 不同的编号含义。本项目不把这些分支已经安装或升级过的数据库直接切换到 self，因为 Gitea 的版本表只保存数字，无法证明同一个数字执行过哪一组迁移。这个边界把兼容承诺集中到真实部署的 self 历史，升级行为可以通过确定的旧版本数据库测试，而不需要猜测表结构来源。

**实现验收点**

- `TestUpgradeSelfDatabaseFrom372` 使用旧结构和真实版本记录执行 372 → 374 升级。
- 版本 372 只有迁移 372、373 待执行，版本 373 只有迁移 373 待执行，版本 374 没有待执行迁移。
- 部署记录能够证明数据库一直沿 self 分支升级。

## 迁移文件身份

官方迁移文件保留上游原始路径和内容，例如 `v365.go` 到 `v369.go`。文件名表达它们在上游的身份，`migrations.go` 决定它们在 self 中的真实执行位置。这样下一轮同步时可以直接逐字比较官方文件，也为未来官方 `v370.go` 和后续文件保留正常位置。

只有两个自维护 PR 的数据库变化使用以下稳定格式：

```text
pr-<PR 编号>-v<最初来源迁移编号>-patch<增量序号>.go
```

例如 `pr-38337-v365-patch3.go` 表示 Codespace PR 最初迁移 365 的第三项后续变化；它在 self 中实际执行为迁移 371。来源身份与执行编号分开记录，是为了在 PR 变基或上游增加迁移后仍能识别同一项自维护变化。

**实现验收点**

- `modelmigration/v29/v365.go` 至 `v369.go` 及现有测试与 `upstream/main` 逐字一致。
- 自维护文件只有 `pr-38337-v365-patch1/2/3` 和 `pr-40071-v365-patch1` 四组来源身份。
- self 迁移目录由四组自维护 PR 文件和官方 `v365`—`v369` 组成，官方后续 `v370.go` 位置保持可用。

本轮以双父合并保存两个 PR 的完整提交记录，再用普通提交整理数据库执行序列：

| 内容 | 提交 | 结果 |

| 合并 Codespace 当前头 | `23ca84e0c82c43f8c457d3736a4ab721b6525c93` | 第二父为 `0f1c19ba10` |
| 合并 Pages 当前头 | `d87314faabe04bd6560d9b39cb422a6f4117c4d7` | 第二父为 `5000d55fb2` |
| 恢复官方迁移文件身份 | `f19882d9babed0ecd7526607c5cc364cd51d7a81` | 官方 `v365`—`v367` 回到原路径 |

非数据库文件与两个 PR 的正常合并结果一致。长期 self 差异集中在 `modelmigration` 中：自维护 PR 迁移文件、self 执行列表和 self 升级测试。

**实现验收点**

- 两个合并提交的第二父分别是固定的 PR 头。
- 排除双方正常合并时需要人工组合的文件后，非数据库文件与 Git 自动合并结果没有差异。
- 人工组合的路由、组织、仓库删除和管理端测试同时保留 Codespace、Pages 与上游行为。
