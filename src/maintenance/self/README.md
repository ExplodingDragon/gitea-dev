# Gitea self 分支维护总览

`self` 是本项目直接维护的 Gitea 分支。它从上游提交 `d3021b69eec62d40752f7034ced4dd091fe085af` 建立，以完整 Git 历史合并 Codespace PR #38337 和 Pages PR #40071，并在 Gitea 原生数据库迁移序列中依次安排两项迁移。

这个分支的目标是让两个仍各自占用上游迁移 365 的 PR 可以同时运行。上游合并前无法为两个 PR 分配同一个迁移编号，因此 `self` 将 Codespace 保留为迁移 365，把 Pages 调整为迁移 366。数据库一旦执行这组迁移，就进入 `self` 的版本含义，后续继续沿 `self` 升级。

两个 PR 通过双父合并提交接入，因而原提交、作者、提交顺序和来源分支关系都可以从 `self` 追溯。迁移文件的命名和编号调整放在独立提交中，使审阅者可以把功能实现与 `self` 的数据库版本安排分开查看。

## 维护边界

`self` 使用 Gitea 现有的 `version` 表、`modelmigration/migrations.go` 和迁移执行流程。每次需要数据库变化时，维护者把函数追加到原生迁移列表末尾，并分配下一个连续编号。这样安装、启动检查、`gitea migrate` 和迁移测试继续走同一条成熟路径。

数据库来源以分支和备份记录为依据。当前支持从分叉前的较低上游版本升级，也支持从明确由 Codespace PR #38337 建立的数据库继续升级。Pages PR 单独建立的同号数据库和分叉后使用相同编号的上游数据库具有不同含义，应从进入这些分支前的备份转入 `self`。具体范围见[数据库版本与升级范围](database-versioning.md)。
