Codespace PR #38337：来源迁移 365 patch4

来源、目的与执行位置

本项接入 Codespace PR 09670abbdecdd30f42a13e1e20b1dd2a625cc527 的新数据库结构。相关来源提交为 24e9558ca9838eb8528ceec668e7127546be5d61（创建时选择密钥并保存快照）和 c334da5d5f73419e11d6d1d7982e57084feb1cc0（数字实例 ID 及 Manager 返回访问地址）。

旧实例使用 UUID，旧个人密钥按仓库关联提供；新实例改用数字 ID，并在创建时明确选择密钥、保存实例自己的加密快照。旧运行资源和新协议无法直接等同。本次审阅确定删除旧实例及关联运行数据，保留可直接继续使用的个人和管理配置，用户升级后重新创建 Codespace。

实现文件为 modelmigration/v29/pr-38337-v365-patch4.go，函数 ResetLegacyCodespaceInstancesAndUpdateSchema 注册为 self 374，完成后版本为 375。名称继续使用最初来源 v365，使 PR 当前完整迁移位于 v370.go 这一事实与 self 执行顺序各自明确。

实现验收点

  • PR 原始提交可沿双父合并追溯，self 迁移为后续普通提交。
  • patch1—patch3、Pages patch1 和官方迁移保持已发布内容。
  • 版本 374 只需执行本项即可到 375。

数据处理范围

对象处理结果原因
codespace 全部旧行删除，包含创建中、运行中、停止、失败、删除中的实例各状态都属于旧协议，统一重新创建
codespace_gitea_token、codespace_open_token、codespace_ssh_key清空，包含孤立关联旧实例消失后这些凭据已经失去用途

个人密钥旧仓库限制被移除，不能把它理解为限制自动迁移到了新结构。新流程按 PR 的创建权限检查及显式选择生成快照；fork PR 等场景继续由 PR 业务逻辑限制复用已保存密钥。本迁移保留密文，不读取明文，也不为旧实例合成快照。

实现验收点

  • 所有状态的旧实例及孤立凭据被清理；普通 SSH 公钥与其他 DBFS 文件保留原值。
  • DBFS 路径匹配转义 _，codespaceXlog/、codespace_log_other/ 不被误匹配。
  • 个人密钥密文、时间和唯一索引保持原值，Manager、模板、授权表快照一致。
  • 最终 Codespace、个人密钥列和索引与当前模型一致。

执行顺序与失败重试

迁移先在同一事务中删除旧实例、凭据、公钥及日志，再增加快照列，按方言元数据删除 UUID 索引和三个旧字段，最后删除旧关联表。任何数据库错误直接返回，由原生迁移器停止升级并保留待执行版本。

DDL 的事务行为因数据库而异，因此不承诺所有步骤整体回滚。清理事务失败时已删除行会回滚；清理成功而后续 DDL 失败时，旧实例可能已经删除，版本仍为 374。修复明确报错后继续使用同一版本重试，已删除的列、索引、表可以接受重复执行。整个升级期间保持业务停止，成功到 375 后才开放服务。

SQLite 使用原生 DROP COLUMN，保留空实例表的自增序列和其余索引；其他数据库使用仓库既有删列实现。各数据库均使用 DELETE 清理实例，不重建实例表或重置自增值，防止新实例重用已删除的历史数字 ID。UUID 索引按列身份识别，以适配 PostgreSQL 返回完整物理名称的情况。

实现验收点

  • 注入清理错误时，Codespace 公钥删除回滚。
  • DDL 失败时版本保持 374，修复后再次执行完成到 375。
  • 迁移前曾删除的最高实例 ID 不被新实例重用。
  • 完成到 375 后再次调用完整迁移器，保留新实例及新令牌。

部署顺序与运行资源清理

本页定义发布时的操作顺序；本次代码合并与测试没有操作现有数据库或集群。

  1. 记录现有 self 提交、数据库版本、Manager 和目标 GiteaSite 的名称、UID。停止所有 Gitea 副本及后台任务，暂停入口请求，避免迁移期间写入旧数据。
  2. 在仍能管理旧资源的 Manager 中禁用目标 GiteaSite，并保留控制器运行以完成清理。只列出 spec.site 的名称及 UID 均匹配该站点的 Codespace 资源。
  3. 使用 Manager 管理端的运行资源删除操作。接口核对资源 UID、resourceVersion 和 Pod UID，并要求所属站点处于禁用状态；若返回资源冲突，刷新身份后重新确认。等待控制器完成 Pod 停止、PVC 删除和运行资源收尾。对保留策略为 Retain 的卷，另按明确卷 ID 处理剩余存储。共享组件及其他站点继续保留。
  4. 确认目标站点旧实例对应的 Pod、PVC、Codespace 资源已清理，再启动本版本执行数据库迁移；版本达到 375 后再恢复入口。迁移错误时保持停机，依据错误修复后重试。
  5. 配套更新 CRD、Manager、Gateway、Agent 及运行镜像。Gitea 当前协议依赖为 gitea.dev/codespace-proto-go@3efecf8a2275，现有 Codespace 来源 e32ab67ed9c00aa36bd86a706b29e3f24a391064 使用相同协议；实际镜像必须由兼容该协议的代码构建，不能仅以标签名称判断。确认就绪后恢复站点调度。
  6. 使用系统 OpenSSH 且启用 Gitea 管理 authorized_keys 的部署，运行 Gitea 既有公钥重建操作，清除旧文件条目。数据库已经移除旧 Codespace 公钥；共享缓存沿正常失效时间处理，无需清空其他业务缓存。
  7. 验证保留的个人密钥、Manager、模板和权限授权；创建新实例，验证密钥选择、数字 ID、访问地址、SSH、日志及停止/恢复/删除。再重启 Gitea，确认新实例仍在。

旧工作目录和日志按本次审阅结论丢弃，不提供旧实例恢复功能。若迁移后需要回退部署，必须使用升级前的完整数据库恢复方案；单独换回旧二进制不能逆向恢复已删除的表、列和数据。数据库快照也不等于旧运行卷的备份。

实现验收点

  • 发布记录包含目标站点 UID、旧资源清理结果、数据库 375 及配套镜像版本。
  • 操作只作用于目标站点，资源仍被使用或身份改变时以明确错误停止处理。
  • 数据库迁移和集群资源清理分别验收；数据库测试通过不代替实际集群验收。
  • 新实例完整生命周期及重复启动验证完成后，部署升级才算完成。

测试与维护记录

直接测试覆盖删除和保留范围、日志路径隔离、保留索引、自增序列及事务回滚；完整迁移测试覆盖 372、374 升级和 375 再次启动。SQLite 另以视图依赖模拟 DDL 中断。所有测试由 Gitea Make 目标启动，各数据库及完整套件的实际结果记在 验证记录。
