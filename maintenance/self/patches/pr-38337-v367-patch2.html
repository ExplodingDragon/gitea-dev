Codespace PR #38337：迁移 367 patch2

来源与目的

本项迁移来自 Codespace PR #38337 的提交 3fc98fc1c089092a2d77978f8d070fe595f595f2。该提交把 Manager 注册流程改为按站点或用户作用域领取注册令牌，并在来源的旧迁移 365 中增加 codespace_manager_registration_token 表。

上一版 self 已经完成迁移 365 和 366，数据库版本为 367。为了让这类数据库执行新建表操作，self 把来源增量安排为下一个迁移 367，并命名为 Codespace patch2。迁移完成后数据库版本为 368。

实现验收点

  • 来源变化提交为 3fc98fc1c0，当前同步 PR 头为 18086bdaa7。
  • migrations.go 将 AddCodespaceManagerRegistrationTokenTable 注册为迁移 367。
  • 文件名为 pr-38337-v367-patch2.go，完成后的数据库版本为 368。

表结构

迁移建立 codespace_manager_registration_token，字段与当前业务模型一致：

字段作用数据库约束
id主键标识XORM 默认主键行为
token40 字符注册令牌唯一索引
user_id0 表示站点作用域，正数表示个人用户作用域普通索引
is_active标记当前令牌是否有效布尔字段
created创建时间created 自动时间
updated更新时间updated 自动时间

用户作用域查询和令牌精确查找是注册、轮换与失效校验的核心路径，因此分别保留用户索引和令牌唯一索引。迁移只负责建立结构，令牌由设置服务首次访问时生成。

实现验收点

  • 表包含 id、token、user_id、is_active、created、updated 六列。
  • token 有唯一索引，user_id 有普通索引。
  • 插入两个相同令牌时，第二次插入返回数据库错误。
  • 迁移执行后，业务模型的 TableName() 与迁移表名一致。

升级行为

全新安装和数据库版本 365 会按 365、366、367 依次建立完整结构。上一版 self 的版本 367 只执行本项。当前 Codespace PR 单独建立的版本 366 已经可能由来源迁移 365 建立该表；它进入 self 后执行 Pages 366，再由本项通过 Sync 幂等确认结构。

这三条路径都由 Gitea 原生迁移器处理，并在完成后记录版本 368。

实现验收点

  • AddCodespaceManagerRegistrationTokenTable 连续执行两次均成功。
  • 旧 self 数据库无需重新执行迁移 365 即可获得新表。
  • 当前 Codespace PR 数据库已有同名表时，迁移 367 可以完成幂等同步。
  • 所有可接受来源完成后数据库版本均为 368。
