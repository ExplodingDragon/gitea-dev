Gitea Pages 与 Codespace 设计文档

上游同步流程

一、固定来源与工作区

每轮先获取 upstream/main、Codespace PR #38337 和 Pages PR #40071 的远端当前头，记录完整哈希和日期。确认内层位于 self 且工作树干净；同时记录外层已有用户改动，后续只暂存维护范围内的文件。

固定来源使一次同步具有可重复的审计边界。PR 若已经包含目标上游提交，就由 PR 合并带入该上游；祖先关系不满足时，再按实际关系设计额外合并。

实现验收点

  • 维护记录包含三个远端来源的完整哈希。
  • 合并前内层分支为 self，没有未提交改动。
  • 外层已有用户改动在同步前后保持未暂存状态。

二、正常合并两个 PR

依次使用双父合并接入两个 PR 当前头，非数据库冲突按“最新上游 + Codespace + Pages”的正常组合行为处理。每次合并单独提交，并在提交信息中记录固定来源头；这样原作者提交、提交顺序和下一轮增量起点都由 Git 保存。

业务冲突需要结合两边测试和调用关系处理，例如仓库删除同时执行 Codespace 解绑、Pages 墓碑更新和上游删除逻辑。解决后比较正常合并结果，确认 self 没有额外业务分支。

实现验收点

  • 每个更新的 PR 都有独立双父合并提交。
  • 合并第二父等于本轮记录的 PR 头。
  • 非数据库结果只表达两个 PR 与上游功能的正常组合。

三、安排 self 数据库迁移

先保留所有官方 vXXX.go 文件和测试，再检查两个自维护 PR 的数据库变化。两个 PR 已经由 self 早期迁移覆盖的完整建表文件不重复注册；真正新增的变化以 pr-<PR>-v<最初来源>-patch<N> 保存。所有待执行函数追加到 self 当前末尾编号。

官方文件身份与 self 执行编号分开，是因为已发布数据库不能重新解释旧编号，而上游文件路径又需要保持可直接比较。下一项实际编号始终由 self 当前末尾决定。

实现验收点

  • 官方迁移文件与上游逐字一致。
  • 自维护 PR 增量具有稳定的 pr-* 文件身份和直接测试。
  • self 迁移编号连续追加，没有改写已发布编号。

四、验证升级和业务组合

迁移测试既要检查编号边界，也要使用上一版真实 self 版本记录执行完整迁移入口。代码验证通过仓库 Make 目标执行格式化、依赖整理、生成检查、静态检查、构建、后端测试、前端测试、迁移测试、集成测试和端到端测试。

集成环境差异记录测试名、工具版本、实际值和期望值。只有已经证明与本轮代码无关的环境差异才作为已知结果记录；新增回归需要在本轮修复。完成后运行 make clean 清理测试产物。

实现验收点

  • 上一版 self 数据库通过完整迁移入口到达新版本。
  • 所有 Gitea 测试都由 Make 目标启动。
  • 清理后内层工作树干净，生成文件没有未提交差异。

五、执行来源与差异审计

完成测试后重新查询远端哈希，确认来源在实施期间没有变化。检查三个来源都是 self 祖先，官方迁移文件与上游一致，并用两个 PR 的正常合并树比较非数据库文件。需要人工解决的正常业务冲突逐项记录组合理由。

这一步把“代码看起来能运行”提升为“结果确实来自已记录来源”。self 长期差异应能集中列在 modelmigration 中，而不是散落在业务路由、服务或前端。

实现验收点

  • 实施前后远端来源哈希一致，或已重新合并变化后的新头。
  • 排除正常人工冲突后，非数据库文件比较没有额外差异。
  • self 特有差异集中为迁移执行安排、PR 迁移增量和升级测试。

六、提交、推送和文档闭环

先提交并推送内层 gitea/self，确认远端可以解析最终提交。随后更新本目录、src/SUMMARY.md、根目录 AGENTS.md 和外层 gitea 指针，构建 mdBook，并只暂存这些维护文件。最后提交并推送外层 main。

先内层后外层可以保证文档和子模块指针引用的提交已经可获取。精确暂存保护外层正在进行的其他设计和子模块修改。

实现验收点

  • origin/self 与内层本地 self 指向同一提交。
  • 外层维护提交只包含明确列出的维护文件和 gitea 指针。
  • origin/main 推送完成后，外层其他用户改动仍保持原状态。
