Gitea Pages 与 Codespace 设计文档

Gitea 服务端

Gitea 是 Codespace 的业务控制面：它确认用户权限、保存用户可见状态、签发短期凭据，并把运行操作交给 Manager。Kubernetes 实现见运行平台。

用户流程

仓库、提交和合并请求页面提供带当前上下文的创建入口；/-/codespaces 提供跨仓库列表；详情页展示状态、访问入口、资源使用、设置和操作日志。用户设置与站点管理分别维护个人对象和全局对象。

跨仓库列表始终只显示当前用户创建的 Codespace，默认覆盖全部源仓库。用户可以按自己的个人仓库或自己所属组织的仓库筛选；这里的选择只限定源仓库所有者，不改变 Codespace 所有权、运行状态或 Manager 绑定。筛选链接不携带页码，因此切换范围后从第一页开始；同一范围内翻页、刷新状态和进入详情后的返回链接保留筛选条件。

创建先锁定提交并解析 Dev Container，再让用户确认环境、配置来源、附加仓库权限、会注入的 Secret 名称和自动停止设置。环境需要明确选择；Manager 暂时离线时，已经声明的环境仍可用于排队。

创建入口依附仓库上下文，集中列表管理已有环境。这样创建时不重复选择仓库，跨仓库管理也有稳定入口。

实现验收点

  • 分支、标签、提交和合并请求进入同一确认流程。
  • 没有可用环境时页面说明基础设施状态，不创建业务记录。
  • 配置、权限或 Secret 范围变化后需要重新确认。
  • 列表只返回当前用户创建的数据，并支持数据库分页。
  • 默认列表包含个人仓库和组织仓库中的 Codespace；个人与组织选项只按源仓库所有者筛选。
  • 切换源仓库所有者后从第一页开始，同一筛选范围内的分页、状态刷新和详情返回保持上下文。

权限与身份

Codespace 归创建用户所有。页面、表单和令牌接口都从当前登录身份重新查找对象；URL 中的 ID 或 UUID 只用于定位。创建至少要求主仓库代码读取权限，附加仓库授权取用户当前权限与已确认范围的交集。

创建者读取详情、日志或提交生命周期操作时，数据库查询同时使用 Codespace ID 和当前用户 ID。这样属于其他用户的对象与不存在对象具有相同结果，服务层也不会把外部对象加载为当前请求的数据。仓库权限与工作区所有权分别处理：用户失去源仓库或附加仓库权限后，已经创建的 Codespace 和工作区文件仍由创建者管理；之后的 Gitea API、Git HTTP、Git SSH、拉取、推送和运行材料签发按用户当时的仓库权限收窄。这个边界让权限撤销立即阻止新的仓库访问，同时避免把仓库权限变化解释为删除用户工作区数据的指令。

Codespace Token 由独立认证方法优先识别。通用 Token scope 与凭据标识通过 Gitea 的 Doer.ExtDoerData 传递，Codespace 仓库授权仍在请求上下文中校验。这样通用权限判断可以沿用 Gitea 的实现，管理员持有的 Codespace Token 也不会获得管理员的完整权限。访问授权范围外的公开仓库时，请求保留 Codespace 用户身份用于审计，同时使用匿名只读的仓库权限。

身份用于说明“谁在请求”，仓库权限用于说明“这次能做什么”。两者分开后，公开仓库读取不会扩大 Token 范围，也不会丢失真实请求者。

权限设置集中读取当前用户的授权、仓库规则和使用数量，关联仓库按批次加载，避免列表增长时逐项往返数据库。撤销后的授权保留展示记录，使用数量归零，修改入口同步关闭；读取失败则报告服务错误，避免把数据库故障误认为授权不存在。

实现验收点

  • 每次读取和修改都重新校验对象、仓库与 Runtime 归属。
  • 创建者详情、日志、Open Code、交互设置和生命周期操作按对象 ID 与当前用户 ID 查询，其他用户得到与对象不存在相同的响应。
  • 用户失去仓库权限后，后续运行凭据同步收窄或停止签发。
  • 协作者关系撤销后，用户仍能查看和管理自己已创建的 Codespace；私有仓库在没有其他读取权限时拒绝 API 与拉取，公开仓库保留公开只读访问，推送始终要求当前写权限。
  • 附加仓库授权不会扩大用户原有权限。
  • Codespace Token 只按 Codespace 权限模型处理。
  • Token scope 和仓库授权同时生效，管理员身份不会绕过 Token 限制。
  • 公开仓库回退仅允许读取，同时保留真实用户身份。
  • 权限列表保持用户隔离、稳定排序和正确的使用数量；权限收窄或撤销后，列表与实际授权同步变化。

Manager 与调度

Gitea 为站点全局范围和每个用户范围分别维护一个可重复使用的 Manager 注册令牌。管理员从 Codespace Manager 管理面提交 Gitea 地址、注册令牌和显示名称；Gitea 根据令牌确定所有者，在同一事务中创建 Manager 并签发该 Manager 独有的运行密钥。注册响应只返回一次运行密钥，Codespace Manager 将它保存到受管 Kubernetes Secret。Gitea 在数据库保存当前范围注册令牌，Codespace 集群侧只在这次请求中使用它，不写入 CR 或 Secret。

注册令牌用于批量接入同一管理范围，运行密钥用于区分已经注册的实例。二者分开后，新增 Manager 不需要修改 Gitea 中的预创建记录，轮换注册令牌也不会中断现有 Manager。管理员可以显式重置范围注册令牌；旧令牌随即停止接受新注册，已经签发的运行身份继续有效。

Manager 注册接口只校验协议版本、注册令牌和名称，不要求运行身份请求头。声明、领取、续期、日志和完成等后续接口都要求 Manager ID 与运行密钥。个人范围令牌只能创建归该用户所有的 Manager，站点令牌创建全局 Manager。

create 以未绑定状态入队。Manager 拉取任务时提交当前可接受的环境标签和本实例剩余容量，Gitea 按所有权、标签和排队顺序选择候选，并通过条件更新完成唯一领取。同一范围内声明相同标签的多个 Manager 共同承担首次创建；没有剩余容量的实例不会领取，其他有容量的实例仍可继续领取。所有实例都没有容量时，任务保留在队列中，待后续请求自动领取。Manager 分配 Runtime UUID 并绑定后，resume、stop 和 delete 都返回同一 Manager，避免生命周期中途迁移持久工作区。

环境标签就是 Manager 集群中 EnvironmentTemplate 的 Kubernetes 资源名。Gitea 以这个名称合并多个 Manager 的声明，因此相同名称表示可以互换的首次放置能力，不同名称表示不同环境。标签只决定首次调度；已有环境恢复时使用创建时保存的配置，因此模板后续修改不会隐式迁移环境。

删除 Manager 会撤销其凭据并清理 Gitea 中绑定的业务记录。确认页面同时说明运行数据需在 Manager 管理面停用对应站点后清理，使业务身份撤销与不可逆的数据删除各自具有明确的操作人和确认步骤。

实现验收点

  • 同一范围注册令牌可以注册多个 Manager，每个 Manager 获得不同的运行密钥。
  • 重置注册令牌后旧令牌不能继续注册，已注册 Manager 的认证保持有效。
  • 注册请求不需要 Manager 身份，其他 Manager RPC 仍同时校验 ID 和运行密钥。
  • 个人注册令牌创建的 Manager 归对应用户所有，不能跨用户领取操作。
  • 并发领取同一操作时只有一个 Manager 成功。
  • 多个 Manager 声明同一环境名时，Gitea 只展示一个环境选项；单个实例容量不足不影响其他有容量实例领取。
  • 所有候选 Manager 容量不足时 create 保持排队，容量恢复后无需重建记录即可领取。
  • Runtime UUID 绑定后保持稳定，后续操作不重新调度。
  • Manager 删除提示明确区分 Gitea 业务记录和运行平台数据的清理。

生命周期与可观测性

Gitea 为 create、resume、stop 和 delete 建立带版本的操作。领取、续期、日志和最终结果需要匹配当前 Manager、Runtime 与操作版本；运行实例版本单独记录成功的 create/resume，使 stop 排队期间的 Runtime 信息仍能准确绑定原实例。完整转换规则见生命周期。

操作日志按单调字节偏移追加，页面按偏移增量读取。CPU、内存、磁盘、Endpoint 和 ready 信息属于可重建的展示数据；过期时显示暂不可用，不据此推测新的业务状态。

实现验收点

  • 非法状态转换在创建操作前返回明确错误。
  • 续期、日志、Runtime 信息和最终结果只接受当前绑定与版本。
  • create/resume 的完成不以展示缓存作为事务前置条件，Endpoint 仍只使用与运行实例版本匹配的 Metadata。
  • 长日志可以分页读取，并保持用户查看历史时的滚动位置。
  • 展示数据过期不会把 running 改为 stopped 或 failed。

凭据、配置与后台任务

Gitea 按用途签发 Git/API Token、一次性 Open Code 和 Gateway 会话授权。Open Code 只保存摘要，并在首次成功兑换时由数据库条件删除。Git SSH 私钥由 Runtime 生成并保存在 PVC，Gitea 只接收公钥；用户 Secret 加密保存，运行时按名称和当前仓库范围请求。

Manager 在 create、resume 或恢复运行材料时请求当前有效内容，并写入 Runtime 易失目录。stop 和 delete 撤销运行期 Token，resume 重新签发。Gitea 配置只表达业务入口、Git 传输、超时和日志策略；集群、镜像、RuntimeClass 与 Cache 由 Manager 管理。

后台任务处理已领取操作的租约和执行时限、自动停止、失效凭据和 Manager 状态核对。尚未领取的 create 和 resume 不消耗执行租约，因此持续等待可用 Manager；用户可以删除尚未领取的 create，或取消尚未领取的 resume。这样基础设施暂时满载不会被记录成运行失败，同时每个等待状态都有明确的用户退出路径。

超时扫描和 Manager 记录清理使用 Codespace 的数据库主键定位，再校验当前版本和状态。Runtime UUID 在首次绑定前为空，不能作为这类数据库内部维护操作的唯一定位条件。

实现验收点

  • Token 权限不超过用户当前权限与确认范围的交集。
  • 同一 Open Code 并发兑换时只有一次成功。
  • 私钥和 Secret 明文不进入普通读取响应或日志。
  • Gitea 启动不依赖 Manager 在线，页面和配置不出现 Kubernetes 选项。
  • app.example.ini 与代码支持的业务配置保持一致。
  • 尚未领取的 create 可以由用户删除，尚未领取的 resume 可以取消并回到 stopped；Manager 已领取后继续由租约和执行时限收敛。
  • Manager 删除时，尚未分配 Runtime UUID 的相关记录同样能够按业务关系清理。
